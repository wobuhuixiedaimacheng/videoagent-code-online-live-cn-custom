## 1. 使用规则

- 每个用例必须在本轮重新执行；历史报告、截图和 JSON 只能证明“以前出现过”，不能继承为当前通过。
- 每个交互缺陷至少保存操作前、操作后截图，记录 Console、失败请求和可复现步骤。
- 所有状态初始为 `TODO`；只有证据位填写完整后才能改为 `PASS / FAIL / BLOCKED`。
- 测试数据不得包含真实密钥、个人隐私或未经授权素材；报告中一律以 `[REDACTED]` 替代密钥。
- 新渐进式流程是当前验收契约；2026-07-01 的“一次生成并合并 12 个 Patch”只作为旧回归来源，不是新流程的正确期望。

### 成本分层

| 层级 | 含义 | 是否允许默认执行 |
|---|---|---|
| `F0` | 静态/命令行、本地构建，无浏览器、无外部 Provider | 免费，可默认执行 |
| `F1` | 浏览器 + Mock Provider，本地交互，不产生模型/视频费用 | 免费，可默认执行 |
| `F2` | 人工响应式、键盘、读屏与视觉检查，无 Provider | 免费，可默认执行 |
| `N1` | 在线规则来源检查，无模型费用，但依赖外网 | 单独报告，不阻断离线结论 |
| `P1` | 真实 Anthropic/OpenAI/Custom 文本模型 | **会产生 Token 费用，需单独批准** |
| `P2` | 真实 Agnes 视频提交、轮询与下载 | **高成本，需逐次明确批准** |

### 统一证据位要求

- UI：截图路径、操作日志、Console 错误汇总、失败请求清单。
- API：请求/响应脱敏 JSON、HTTP 状态、耗时、重试次数、关联 ID。
- 数据：操作前后 workspace/本地存储导出或可见文件版本证据。
- 性能：冷/热加载样本、关键交互耗时、LCP/CLS/长任务或同等指标。
- 可访问性：键盘路径、可访问名称/状态、对比度与读屏记录。

## 6. 推荐执行顺序与门禁

1. 先跑 `FREE-001～008`；任何构建、离线安全校验失败时，不进入浏览器 QA。
2. 再跑全部 `F1/F2`；先 Mock 完整主链，再测异常、数据、响应式、可访问性、性能和安全。
3. `P1` 只在免费层全部无 Critical/High 阻断后执行；先单 Provider 单 Mission，再做跨 Provider。
4. `P2` 必须在上游阶段、幂等、费用门和 Network 负向验证通过后执行；先一个 7 秒镜头，后多镜头。
5. 每发现缺陷立即落证据并复测一次；修复后还需跑相邻流程和本矩阵对应历史回归项。

### 发布验收门

- `F0/F1/F2` 所有 Critical/High 用例通过；无未解释 Console error、失败请求或横向溢出。
- 生产阶段不能跳级；确认、幂等、stale、迟到回调和刷新恢复均有当前证据。
- 七平台逐一通过；stale/unknown/estimated 不得冒充确定规则；Remotion 保持 disabled/reference_only。
- 未批准时不产生真实文本/视频费用；真实任务的请求数和费用可核对。
- 不存在密钥泄露、越界 Patch、自动发布/账号操作、Prompt 注入越权或服务端 warning 被模型覆盖。
- 如果 `P1/P2` 未获批准，最终报告必须写 `BLOCKED - 未授权付费验证`，不能以 Mock 结论代替。
