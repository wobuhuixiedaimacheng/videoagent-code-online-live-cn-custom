# VideoAgent 渐进式阶段确认设计

日期：2026-07-11  
状态：书面规格已确认，待实施  
适用范围：VideoAgent Mission 画板的脚本、角色、场景、分镜和视频生成主流程

## 1. 问题定义

当前工作台虽然有“总览、剧本、角色、场景、分镜、视频”阶段，但它们本质上仍是可以任意切换的页面标签。

现有“确认并继续”只切换当前阶段，没有完成以下关键动作：

- 没有冻结用户刚刚确认的资产版本；
- 没有把当前确认作为下一阶段生成的唯一输入；
- 没有阻止用户跳过尚未确认的阶段；
- 上游资产修改后，没有可靠地使下游资产失效；
- 画板一开始就展示大量节点，用户无法判断此刻真正需要审查什么。

因此，当前交互表达的是“浏览不同页面”，不是“逐步完成一条视频生产链路”。

## 2. 产品目标

把 Mission 画板改成渐进展开的生产流程：每个阶段先生成可见资产，用户审查并确认，系统再以该确认版本生成下一阶段。

目标流程：

> 用户目标 → 脚本待确认 → 角色待确认 → 场景待确认 → 分镜待确认 → 视频任务待确认 → 视频渲染 → 成片

每次确认必须同时完成三件事：

1. 合并并冻结当前阶段用户看到的版本；
2. 记录确认人、确认时间、资产版本和上游依赖版本；
3. 启动下一阶段的专项生成任务。

## 3. 非目标

本次不做以下内容：

- 不实现真正的人脸向量库或云端 Face ID 服务；
- 不重做模型配置和供应商连接；
- 不修改视频模型 API 协议；
- 不把 Agent 运行日志重新放回主画板；
- 不照搬 OiiOii 的品牌色、字体和黑色皮肤。

借鉴的是“画板优先、资产节点、逐步展开和用户确认门”，不是视觉复制。

## 4. 阶段与状态

### 4.1 阶段顺序

固定生产顺序：

1. `script`：完整脚本；
2. `character`：角色主图、Face ID、年龄阶段、多视角和表情；
3. `scene`：场景图、地点、时间、光线和整体风格；
4. `storyboard`：镜头、动作、对白、时长和运镜；
5. `video`：镜头级视频任务审查、提交、渲染状态和最终成片。

`overview` 只负责展示总体进度，不参与确认链路。

### 4.2 状态模型

每个阶段使用统一状态：

- `locked`：上一步尚未确认，当前阶段不可进入；
- `generating`：正在生成阶段资产；
- `ready_for_review`：资产已生成，等待用户确认；
- `confirmed`：当前资产版本已确认；
- `stale`：上游版本已变化，当前资产已过期并需要重审；
- `rendering`：仅用于视频阶段，已确认的视频任务正在渲染；
- `completed`：仅用于视频阶段，全部镜头已经完成并形成可预览成片；
- `failed`：生成失败，可以重试，不影响上一步已确认版本。

界面文案对应：

- `locked` → 未解锁；
- `generating` → 生成中；
- `ready_for_review` → 待确认；
- `confirmed` → 已确认；
- `stale` → 需重审；
- `rendering` → 渲染中；
- `completed` → 已完成；
- `failed` → 生成失败。

## 5. 用户流程

### 5.1 脚本确认

初始画板只出现用户目标和脚本节点。

脚本节点必须展示完整正文，而不是摘要。用户可以：

- 直接编辑；
- 提交局部修改；
- 重新生成；
- 对比版本；
- 点击“确认脚本并生成角色”。

点击确认后：

1. 合并当前 `script.md` 待审 Patch；
2. 记录脚本确认版本；
3. 将角色阶段改为 `generating`；
4. 调用角色专项生成；
5. 角色资产返回后，将角色阶段改为 `ready_for_review`；
6. 画板从脚本节点下方展开角色节点。

### 5.2 角色确认

角色阶段必须显示真实角色资产，而不是只有文本设定。

用户需要检查：

- 每个角色是否已生成角色图；
- 主角不同年龄阶段是否自然变化；
- Face ID 是否正确；
- 多视角和表情是否满足后续镜头；
- 是否存在换脸、年龄错误或风格漂移；
- 哪张角色图会进入视频任务。

所有必需角色都有可用主图后，才能点击“确认角色并生成场景”。

点击确认后：

1. 合并当前 `characters.json` 角色资产 Patch；
2. 冻结角色引用 URL、Face ID 和阶段版本；
3. 将场景阶段改为 `generating`；
4. 调用场景专项生成；
5. 场景返回后，在角色节点下方展开场景节点。

### 5.3 场景确认

每个场景节点必须显示：

- 场景主图或多图参考；
- 地点；
- 时间；
- 光线；
- 色彩与现实风格；
- 出场角色；
- 对应脚本段落。

用户可以逐个重生成或替换场景，也可以一次确认本阶段全部场景。

点击“确认场景并生成分镜”后，冻结 `scenes.json` 当前版本并生成分镜。

### 5.4 分镜确认

分镜阶段展示镜头卡和时间线。每张镜头卡显示：

- 对应脚本段落；
- 使用的角色和场景资产；
- 景别；
- 运镜；
- 动作；
- 对白或旁白；
- 时长；
- 首帧或关键帧引用。

点击“确认分镜并生成视频任务”后，Video Generation Agent 只准备可审查的视频任务包，不能直接调用视频模型。

### 5.5 视频生成

视频阶段只使用已确认的脚本、角色、场景和分镜版本。任务包必须逐镜展示：

- 使用的角色、场景、首帧和尾帧引用；
- 视频提示词、负面提示词和模型规格；
- 镜头时长、画幅、动作、运镜和对白；
- 预计生成的片段数量及拼接顺序；
- 尚未满足的角色一致性或素材依赖。

用户可以编辑、替换引用或重新准备单个镜头任务。点击“确认视频任务并开始生成”后：

1. 冻结当前视频任务包版本；
2. 将视频阶段改为 `rendering`；
3. 按镜头提交视频模型任务，并持续显示每个任务的状态；
4. 全部镜头成功并完成拼接后，将视频阶段改为 `completed`；
5. 部分镜头失败时保留成功结果，只重试失败镜头。

任何阶段处于 `locked`、`ready_for_review`、`stale` 或 `failed` 时，都不能开始最终视频生成。

## 6. 画板交互

### 6.1 渐进展开

画板不再一次展示完整流程。显示规则：

- 已确认阶段保留在画板上；
- 当前待确认阶段作为视觉焦点；
- 正在生成的下一阶段显示骨架节点；
- 更远的未来阶段不显示节点；
- 顶部阶段导航可以显示未来阶段，但必须禁用并标记“未解锁”。

### 6.2 镜头移动

阶段确认后，画板自动移动到新生成的节点组。用户返回已确认阶段时，画板只改变镜头位置，不重新生成内容。

### 6.3 详情按需出现

主画板只展示资产和关系。以下内容放到右侧检查器或抽屉：

- Patch Diff；
- 依赖版本；
- 审批记录；
- Agent 执行日志；
- 模型和生成规格；
- 高级错误详情。

脚本正文、角色图、场景图和分镜卡不能再被挤到画板下方的独立文档区。

## 7. 确认与版本规则

### 7.1 确认即审批

阶段内的主确认按钮就是用户对该阶段可见资产的最终审批，不再要求用户先审批 Patch、再点击一次阶段确认。

高级用户仍可以在检查器里查看 Patch Diff，但普通用户只需要理解“确认当前成果”。

### 7.2 上游修改使下游失效

失效规则：

- 脚本修改：角色、场景、分镜、视频全部变为 `stale`；
- 角色修改：场景、分镜、视频变为 `stale`；
- 场景修改：分镜、视频变为 `stale`；
- 分镜修改：视频变为 `stale`。

旧资产保留用于比较，但不能继续进入视频生成。

### 7.3 重新确认

用户确认新的上游版本后，系统重新生成直接下游。更远下游保持 `stale`，直到链路逐级重新确认。

不允许通过一次按钮静默确认全部过期阶段。

## 8. 协作模式与托管模式

### 8.1 协作模式

脚本、角色、场景、分镜和视频任务都必须由用户明确确认，不能自动越过。

### 8.2 托管模式

托管模式可以在后台预生成下一阶段草稿，以减少等待时间，但仍不能替用户确认任何阶段，也不能自动提交视频模型任务。

预生成资产必须标记为草稿；如果用户修改当前阶段，旧预生成资产立即作废。

## 9. 数据设计

新增项目文件 `production_flow.json`，作为阶段状态和确认版本的唯一持久化来源。

建议结构：

```json
{
  "currentStage": "character",
  "stages": {
    "script": {
      "status": "confirmed",
      "draftVersion": 4,
      "confirmedVersion": 4,
      "confirmedAt": "2026-07-11T12:00:00.000Z",
      "confirmedBy": "local-user",
      "sourceVersions": {
        "brief.json": 2
      }
    },
    "character": {
      "status": "ready_for_review",
      "draftVersion": 1,
      "confirmedVersion": null,
      "confirmedAt": null,
      "confirmedBy": null,
      "generationJobId": "character-job-01",
      "sourceVersions": {
        "script.md": 4
      }
    },
    "scene": {
      "status": "locked",
      "draftVersion": null,
      "confirmedVersion": null,
      "confirmedAt": null,
      "confirmedBy": null,
      "sourceVersions": {}
    }
  }
}
```

确认动作直接更新工作区和 `production_flow.json`。生成动作仍通过现有 Agent API 返回阶段资产 Patch，待用户在该阶段主确认按钮中一并合并。

确认事务必须携带当前 `draftVersion` 和幂等键。当前本地版在工作区事务函数中校验版本和状态；后续接入云端项目存储时，同样的校验必须下沉到服务端。这样可以避免重复点击或迟到回调把新版本覆盖成旧版本。

所有生成回调必须携带 `generationJobId` 和 `sourceVersions`。与当前记录不匹配的结果只进入历史版本，不能改变当前阶段状态。

## 10. 错误处理

- 下一阶段生成失败时，上一步保持 `confirmed`，画板聚焦失败的下一阶段；
- 失败节点显示用户可理解的原因和“重新生成”按钮；
- 不删除上一个成功资产；
- 不把失败误显示成“待确认”；
- 重试创建新的 `generationJobId`，迟到的旧任务结果不得覆盖重试结果；
- 视频部分镜头失败时保留成功镜头，只重试失败任务；
- 页面刷新后必须从 `production_flow.json` 恢复进度；
- 缺少阶段文件时，状态必须降级为 `failed` 或 `stale`，不能只靠前端状态假装已确认。

## 11. 验收标准

1. 新 Mission 在脚本生成前不能进入角色、场景、分镜或视频阶段。
2. “确认脚本并生成角色”会合并脚本版本、持久化确认状态并启动角色生成。
3. 角色生成完成后，画板出现真实角色卡，场景阶段仍保持锁定。
4. 必需角色缺少主图时，“确认角色并生成场景”不可用。
5. 角色确认后，场景生成并在画板中渐进展开。
6. 修改已确认脚本会让角色、场景、分镜和视频进入“需重审”。
7. 分镜确认后只生成可审查的视频任务包，不会自动调用视频模型。
8. 存在未确认或需重审阶段时，“确认视频任务并开始生成”不可用。
9. 视频任务确认后才提交模型，部分镜头失败可以单独重试且不会丢失成功镜头。
10. 页面刷新后，阶段状态和确认版本不丢失。
11. 协作模式不能自动越过任何确认门。
12. 托管模式只能预生成草稿，不能替用户确认阶段或提交视频任务。
13. 顶部未来阶段标签不可点击，并明确显示未解锁原因。
14. 重复确认、迟到回调和旧版本生成结果不能覆盖当前版本。
15. 主画板不再同时展示下方长脚本区、审批区和运行日志。

## 12. 验证策略

- 状态机单元测试：覆盖合法转换、非法跳级、上游失效和重试；
- 持久化测试：覆盖确认版本、来源版本、刷新恢复和缺失文件降级；
- 接口测试：覆盖幂等确认、重复点击、迟到回调和部分视频任务失败；
- 浏览器流程测试：从新 Mission 依次确认脚本、角色、场景、分镜和视频任务；
- 响应式检查：桌面和移动端都能看到当前待确认资产、锁定原因和主操作按钮。

## 13. 实施边界

第一期先完成：

- 阶段状态模型与 `production_flow.json`；
- 脚本确认 → 角色生成；
- 角色确认 → 场景生成；
- 场景确认 → 分镜生成；
- 分镜确认 → 视频任务审查；
- 视频任务确认 → 提交生成并显示镜头状态；
- 上游修改导致下游失效；
- 画板渐进展开和阶段导航锁定。

第二期再考虑：

- 服务端媒体合成与单一成片文件；
- 云端 Face ID 向量库；
- 多人实时协作；
- 跨项目角色资产复用；
- 阶段版本时间线和分支比较。
